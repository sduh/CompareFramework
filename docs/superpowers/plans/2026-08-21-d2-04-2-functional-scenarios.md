# D2-04.2 Functional Scenario Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automate the official T001-T010 functional regression catalogue through real LibreOffice 7.4.7.2, the freshly built CompareFramework monolith, UNO orchestration, native CompareFramework output sheets, and strict `actual.json` versus `expected.json` contracts.

**Architecture:** Reuse the D2-04.1 UNO process/injection primitives, but run every functional scenario in its own LibreOffice process, temporary user profile, and working document. Python prepares `MODELE` and `TARGET` from the existing CSV datasets and invokes the technical `CF_CI_RunScenario`; LibreOffice Basic executes the real reference-comparison path, while Python only extracts native result sheets into a normalized JSON contract and performs strict equality against the canonical expectation.

**Tech Stack:** LibreOffice 7.4.7.2, LibreOffice Basic, Python 3, PyUNO/UNO, CSV, JSON, GitHub Actions `ubuntu-22.04`, Python `unittest`.

**Spec:** `docs/superpowers/specs/2026-08-21-d2-04-2-functional-scenarios-design.md`

## Global Constraints

- LibreOffice **7.4.7.2** is the only runtime baseline for D2-04.2.
- The tested Basic artifact is the monolith generated by `tools/build_monolith.py`; direct injection of individual `src/*.bas` files is forbidden.
- Every T001-T010 scenario uses a distinct LibreOffice process, temporary profile, and working document.
- `expected.json` is the canonical machine expectation; `expected.md` remains human documentation.
- `actual.json` is derived only from native CompareFramework output sheets, never from Python reimplementation of comparison logic.
- `CF_CI_RunScenario` is a technical CI entrypoint outside `CompareFramework_API.bas` and outside the six frozen user-facing APIs.
- `CF_CI_RuntimeSmoke` remains unchanged as the D2-04.1 smoke contract.
- The normalized result schema contains exactly: `scenario_id`, `decision`, `added_rows`, `deleted_rows`, `modified_rows`, `modified_cells`, `duplicate_ids`, `structure_alerts`.
- The complete suite must continue after an individual scenario failure so CI can report every failing case.
- D2-04.2 is not `VALIDATED` until a fresh GitHub Actions run succeeds on the final PR HEAD, with D2-03.24, D2-04.0 and D2-04.1 checks also green.
- Documentation and reports are maintained in English and French, with `_FR.md` equivalents carrying the same status and evidence.

```basic
Public Sub CF_CI_RunScenario()
    Dim previousSilent As Boolean
    Dim previousMode As String
    Dim previousSelected As String

    On Error GoTo Cleanup

    previousSilent = CF_REFERENCE_SILENT
    previousMode = CF_REFERENCE_TARGET_MODE
    previousSelected = CF_REFERENCE_SELECTED_TARGETS

    CF_REFERENCE_SILENT = True
    CF_REFERENCE_TARGET_MODE = "SELECTED"
    CF_REFERENCE_SELECTED_TARGETS = "TARGET"

    CF_RunAgainstReference "MODELE", "ProductId"

Cleanup:
    CF_REFERENCE_SILENT = previousSilent
    CF_REFERENCE_TARGET_MODE = previousMode
    CF_REFERENCE_SELECTED_TARGETS = previousSelected
End Sub
```

The procedure must call the existing real reference engine and must not contain row/cell comparison logic.

# D2-04.2 — Functional Scenario Automation Report

**Status:** IMPLEMENTED — verification pending

## Scope

D2-04.2 automates the official T001-T010 functional regression catalogue through real LibreOffice 7.4.7.2 and the UNO harness introduced by D2-04.1.

## Implemented contract

- LibreOffice baseline is pinned to exactly **7.4.7.2**.
- The tested Basic artifact is the monolith generated by `tools/build_monolith.py`.
- Every T001-T010 scenario uses its own LibreOffice process, temporary user profile, and working Calc document.
- Each dataset now has a canonical `expected.json` machine contract; `expected.md` remains the human-readable documentation.
- `CF_CI_RunScenario` is a technical, non-interactive CI entrypoint outside `CompareFramework_API.bas` and outside the six frozen user-facing APIs.
- Python prepares `MODELE` and `TARGET`, invokes the real Basic reference-mode comparison, reads native CompareFramework output sheets, writes `actual.json`, and performs strict contract equality.
- Python does not reimplement CompareFramework row/cell comparison logic.
- `actual.json` is derived from native `Stats_Comparaison` and `Compare_Reference_Summary` outputs.
- T001-T010 continue independently after individual failures so all failing scenarios can be reported in one run.
- Failure artifacts are preserved under `build/d2-04-2` and uploaded by GitHub Actions.

- T001 PASS through T010 PASS;

Runtime evidence will be added to this report only after those checks succeed on the exact final HEAD SHA.
